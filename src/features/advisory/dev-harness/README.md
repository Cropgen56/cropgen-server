# dev-harness: integration tests without a database or network

Runs the **real** advisory services, controllers, queue, pipeline and rules engine against small in-memory fakes:
- `fake_modules/`: mongoose (in-memory), axios (scripted HTTP via `globalThis.__HTTP__`), bullmq, node-cron, openai, express, @turf/convex;
- `src/`: minimal stand-ins for backend models, services, utils and constants that live outside `features/advisory`.

```bash
sh dev-harness/sync.sh                 # copies fake_modules → node_modules and the advisory code → src/features/advisory
cd dev-harness && node --test --test-concurrency=1 --test-force-exit tests/integration.test.mjs
```

The tests cover:
- monitor runs (events, snapshots, notifications);
- no duplicate events or notifications on a repeat run;
- WhatsApp bundling and quiet hours;
- radar waterlogging;
- a missing S1 endpoint;
- the events / feedback / condition APIs;
- the pipeline in `rules` and `shadow` mode;
- chunked season weather;
- no duplicate alerts between the daily advisory and the monitor.

**Limits:** the stand-ins are not your real models or calculators (`gddCalculator`, `cropHealth`, `npkCalculator`). Passing here proves the wiring and logic, not the production data. Run the staging rollout steps in `docs/DEPLOY.md` before going live.
`node_modules/` and `src/features/` are generated by `sync.sh`; don't commit them.
